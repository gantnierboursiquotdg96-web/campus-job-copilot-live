# 输出模板

按以下顺序交付完整分析。事实、分类推断和未知项必须使用不同措辞。

## 1. 画像确认

提出 6 至 8 个问题，只补当前过滤和评分必需字段。先复述已确认的毕业年份、学历专业、岗位方向和城市，避免重复提问。

## 2. 简历证据摘要

依次列出：教育、技能、实习、项目、量化成果、未知项。每个能力结论引用简历中的具体经历文本；裸技能列表不算经历证据。不要补写用户未提供的经历或数字。

## 3. 推荐总览

展示：

- 数据版本 `dataset_version`
- 有效记录数 `valid_records`
- 损坏并跳过记录数 `skipped_records`
- 使用的运行日期和硬过滤说明
- 是否由用户手动放宽届别

## 4. 推荐分组

三组合计最多 15 条，组内保留搜索脚本顺序：

1. `立即投递`：分数至少 65，且紧迫度为 `立即处理` 或 `本周处理`。
2. `重点准备`：分数至少 65，且不属于上一组。
3. `保底与探索`：分数 50 至 64。

分组只改变展示位置，不修改 `score`、`tier` 或全局排序依据。空组可以省略。

## 5. 单条机会

每条使用以下固定字段：

```markdown
### 公司 | 岗位原文
- 机会 ID：`opportunity_id`
- 匹配度：score/100（tier）
- 紧迫度：urgency
- 匹配理由：引用画像字段、简历证据、岗位字段或明确标注的 taxonomy 分类映射
- 主要差距：gaps 和尚未确认的信息
- 简历调整：只建议重排、突出或量化已有经历；没有依据时写“暂无可确认调整”
- 截止原文：deadline_raw；缺失时写“未提供，需核实”
- 投递链接：application_url；缺失时写“需人工查找官方入口”
- 公告链接：announcement_url；缺失或 verification_required=true 时追加“请核实官方公告”
```

## 6. 未来 7 天计划

只使用用户明确选择或清晰优先的机会。每天至少包含：目标岗位、动作、完成标准。按紧迫度安排公告核实、公司调研、已有简历内容调整、投递、笔试准备和跟进；不得承诺自动投递。

## 7. 投递记录

先请用户明确选择具体机会。选择后：

1. 立即 `list` 并读取最新 SHA-256 revision。
2. `add` 时仅传入被选择机会的 JSON 对象，不批量加入推荐结果。
3. `update` 状态或备注前再次 `list`。
4. revision 冲突或 CSV 损坏时停止，不覆盖原文件。
5. 报告只写到工作区 `reports/`。
