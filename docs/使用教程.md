# 校招助手安装与使用教程

这份教程帮助你安装校招助手，并用自己的简历筛选招聘机会、生成七天行动计划和记录投递进度。助手每次推荐前读取卖家持续更新的飞书信息库。首次使用需要安装和飞书授权；配置完成后通过自然语言使用。

## 二、使用前准备

准备一台电脑、飞书账号和支持本地Skill及命令执行的AI工具。当前版本已在Codex环境验证；WorkBuddy等其他工具尚未完成兼容性验收，不能保证相同步骤均适用。普通网页聊天窗口未必能安装和运行本Skill。

助手需要Python 3.10或更高版本、Node.js/npm、飞书CLI。你可以让AI检查并协助安装，不用先学会命令行。AI工具和账号本身是否收费，以你使用的平台为准，本安装包不包含平台订阅。

先用自己的飞书账号打开信息库，确认能阅读。首次配置期间请预留时间，在AI工具与飞书官方授权页面之间完成操作。

## 三、通过GitHub仓库安装

打开AI工具的对话窗口，复制下面这段话发送：

```text
请从这个GitHub仓库安装校招助手：
https://github.com/gantnierboursiquotdg96-web/campus-job-copilot-live

技能名称和安装目录名使用 campus-job-copilot，仓库根目录就是Skill。
请完整安装SKILL.md、agents、scripts、references、assets和LICENSE，
不要只复制SKILL.md，也不要安装原作者的旧快照版本。

安装后检查Python 3.10+、Node.js/npm和飞书CLI是否可用。
缺少依赖时请协助安装。随后按references/live-setup.md，
引导我用自己的飞书账号配置应用并授权。
需要我在官方页面操作时，请给出入口和明确步骤。
不要索取或使用卖家的应用密钥和登录凭证。
```

仓库名是 `campus-job-copilot-live`，Skill名称是 `campus-job-copilot`。保持技能目录名正确，可避免后续调用找不到技能。

如果AI提示已存在同名Skill，先让它确认是不是本仓库的实时版本，并备份你的旧版本及个人数据，再更新。安装完成后开始新一轮对话，确认工具能发现 `$campus-job-copilot`。

## 四、首次完成飞书配置与授权

安装Skill只是第一步。助手还需要以你的账号读取飞书信息库，首次需要你在官方页面完成操作。

让AI依次处理：

1. 检查 `lark-cli --version`。
2. 配置你自己的飞书CLI应用。新用户通常由AI运行 `lark-cli config init --new --brand feishu --lang zh`，并按官方页面完成配置。已有应用和配置时先检查，不重复新建。
3. 发起Base业务域授权。AI运行 `lark-cli auth login --domain base --no-wait --json`，把本次授权链接和二维码展示给你。
4. 在飞书官方页面确认授权，回到AI对话回复“已授权”。
5. AI执行本次授权码的后续登录步骤，并检查 `lark-cli auth status --verify --json`。

Base域授权可能包含写权限；本校招助手只调用招聘表的读取命令，不向信息库上传简历或写入记录。请阅读官方页面列出的权限再确认。授权链接过期时，让AI重新生成，不要一直点旧链接。

你可以直接说：

```text
请检查校招助手的飞书配置和用户登录状态。
如果尚未完成，请按这个Skill的安装授权说明协助我配置。
展示官方授权链接及二维码，我会完成授权后回来告诉你。
完成后请验证用户身份和信息库读取权限。
```

浏览器里能看表，并不保证CLI一定能读：还要满足应用权限和源表访问权限。失败时让AI解释实际错误，不要把卖家的凭证当作解决办法。

## 五、第一次推荐岗位

上传PDF、Word或文本简历，替换下面的毕业年份、专业、岗位和城市，然后发送：

```text
使用 $campus-job-copilot，先读取最新校招信息库。

我是2027届本科生，专业是工商管理。
希望找电商运营、用户运营或运营管理培训生岗位。
优先北京、上海、广州，可以接受笔试。
企业偏好是电商、消费品和零售，企业规模不限。
我的简历已作为附件上传。

请先分析简历，补问必要信息，再推荐适合研究的机会，
解释匹配理由、主要差距及待核实信息。
请显示本次数据读取时间、数据版本和完整读取条数。
等我选定机会后再制定七天计划，不要自动添加全部推荐。
```

没有文件时可以直接粘贴简历正文。只提供必要的求职信息，可以先去掉身份证号、详细住址等不影响匹配的信息。简历会由你使用的AI平台处理；本Skill不会把简历上传到飞书招聘表。

如果目标尚不明确，可以说：

```text
使用 $campus-job-copilot，先分析附件简历中的经历证据。
我暂时不确定岗位方向，请提出适合探索的方向并解释依据。
在我确认方向后，再读取最新信息库推荐机会。
```

## 六、怎么看推荐结果

检查这五项：

| 项目 | 你需要确认什么 |
| --- | --- |
| 本次数据读取时间 | 这轮确实重新读取了信息库 |
| 完整读取状态和条数 | 不是只取了前几条样本 |
| 推荐理由 | 能对应你的专业、偏好或简历具体经历 |
| 差距与未知项 | 届别、具体JD、笔试、城市和截止要求有哪些尚未确认 |
| 公告与投递入口 | 最终以企业官方说明为准 |

匹配分是分类排序参考，不代表录用概率。100分也不意味着满足所有岗位要求。一条数据可能包含多个岗位和城市，需核实你选的具体岗位是否真的在目标城市招聘。

“最新读取”表示读到了表当前的数据，不代表表中每条历史招聘都仍开放。“尽快投递”“招满即止”和缺少年份的日期不能当作准确截止日期。

## 七、选定后生成七天计划

推荐结果会给出稳定的机会ID。复制你选中的ID发送：

```text
我选择以下机会ID：
［粘贴第一个机会ID］
［粘贴第二个机会ID］

请重新读取信息库，核查这些记录是否仍存在、是否有条件变化或过期。
如有问题先向我说明。
然后仅围绕我选定的机会制定未来七天计划，
每天写明目标岗位、具体动作和完成标准。
请把选定的机会加入本地投递记录。
```

计划可以包括公告核实、公司调研、简历调整、官网投递、笔试准备和跟进。简历调整只能使用已有经历，助手不会代你自动提交招聘网站申请。

## 八、记录投递进度

有两种记录位置，你可以选择使用：

- **Skill本地记录**：让AI维护个人工作区中的投递CSV。例如“机会ID……已经投递，请更新状态并记录今天的日期”。
- **飞书个人模板**：先创建副本，再手动填入公司、岗位、入口、阶段、下一步行动和跟进日期。

两者目前不会自动同步。你在飞书副本修改状态，不会自动改变Skill本地记录；向AI更新本地记录，也不会自动写入飞书副本。请选择主要记录位置，避免两边进度不一致。

## 九、数据更新与Skill更新

| 发生什么变化 | 你需要做什么 |
| --- | --- |
| 卖家在同一表新增、修改或删除招聘信息 | 下次推荐自动重新读取，无需重装 |
| 你改变城市或岗位偏好 | 告诉AI更新画像并重新推荐 |
| GitHub发布了新的脚本或规则 | 让AI备份后更新Skill，不覆盖个人数据 |
| 卖家更换来源表或重建字段 | 可能需要安装新的配置版本 |

更新时可以说：

```text
请检查这个仓库是否有更新：
https://github.com/gantnierboursiquotdg96-web/campus-job-copilot-live
如需更新，请先备份已安装版本，保留我的个人工作区、画像和投递记录，
再更新 campus-job-copilot。请说明本次更新的内容。
```

## 十、常见问题

**AI说找不到Skill。**
让它检查技能目录名是否是 `campus-job-copilot`，目录下是否直接存在 `SKILL.md`，安装是否完整，以及当前AI工具是否支持本地Skill。安装后再开始新一轮对话。

**GitHub仓库下载失败。**
这是安装阶段的问题。可以稍后重试，或使用卖家提供的同版本压缩包备用安装；不要用原作者旧数据版本替代实时版本。

**提示Python或lark-cli命令不存在。**
把错误交给AI，让它检查依赖与PATH。安装后可能需要重启终端或AI工具，才能发现命令。

**表格可阅读，但CLI报无权限。**
让AI检查登录账号、应用授权范围和源表阅读ACL。不同组织策略可能限制访问；先修复权限，助手不能绕过限制。

**读取期间数据库发生变化。**
助手会停止，避免用不同版本拼接结果。可以从头重试一次；若仍变化，稍后再试。不会悄悄使用以前的快照。

**想每天自动提醒。**
当前版本按你发起的请求工作，不会后台持续监听、每天主动提醒或自动投递。日常推荐会重新读取数据。

**个人模板无法编辑。**
确认打开的是你创建的副本。源模板是只读的，不要申请源模板编辑权限。
